# RPG 작업실 중심 대시보드 재설계 검토안

상태: 1차 운영 반영·실제 화면 검증 완료 (후속 사용자 “진행”으로 배포 승인). 2·3차는 후속 검토 범위. 작성: 2026-10-16 KST.
관측: 2026-10-16 00:39 KST, 실제 LAN 대시보드 Chromium.
검토 대상 런타임: `41339f4dc09de5363e0d`.
1차 화면 구현·검토·검증 및 원본 선택 반영 후 별도 “진행” 지시로 운영 배포했다. 실행 권한 부여·2·3차 범위는 별도다.

## 목표와 사용자 의도

사용자가 요청한 목표는 대시보드에서 불필요한 요소를 줄이고 프로젝트 및 AI의 업무를
쉽고 재미있게 확인·디버깅하는 것이다. 구체 예시는 스킬 사용 액션, 캐릭터와 대화,
장비 교체, 직업별 개성이다. 기존의 2D RPG 방·이동·말풍선을 살린다.

제안하는 핵심 경험은 '프로젝트 선택 → 현재 임무 확인 → 캐릭터의 행동 보기 →
클릭해 원인과 로그 확인 → 필요한 후속 작업 요청'이다. 게임 표현이 실제 업무를 찾는
탐색 수단이 되게 한다. 수치·원인·스킬 사용을 근거 없이 생성하지 않는다.

대화 범위 질문은 아직 답변 전이다. 이 초안은 '기록 설명 + 기존 웹 채팅/에이전트로
작업 요청 연결'을 기본 가정으로 한다. 대시보드 안에서 자유 AI 대화까지 원하면
아래 3차 범위에서 사용 모델/대상 세션/실행 경로를 확정해야 한다.

4. 오류 수의 오해: '최근 실패 43'과 지도 '확인 필요 45'는 서로 다른 범위/분류다.

5. 디버깅 입구 부족: 캐릭터 상세가 '상태 미확인'을 반복하고 기록은 Bash·요청 반환으로

## 검토한 접근과 선택

| Approach | Strength | Main cost | Decision |
| --- | --- | --- | --- |
| Compact console | Small UI change | Weak character meaning | Partial reuse |
| RPG operations workspace | Clear work and playful debugging | Identity and event work | Recommended |
| Full autonomous simulation | Rich interaction | New agents, cost and scope | Defer |

추천은 두 번째다. 먼저 기본 화면을 단순화하고 기존 실제 이벤트만으로 행동을 명확히 만든다.
스킬명 수집과 실제 대화/장비 설정은 그 다음 연결한다. 경험치·재화·무작위 배회·가짜 진행률은
이번 제품 목표에 도움이 없어 넣지 않는다.

## 정보 구조

```text
+-------------------------------------------------------------+
| Project | Current mission | Working | Attention | Settings   |
+---------------------------------------+---------------------+
|                                       | Selected character  |
|              WORKROOM                 | Mission / State     |
|                                       | Skills / Result     |
|                                       | Talk / Trace / Log  |
+---------------------------------------+---------------------+
| Recent events                       [Open full history]      |
+-------------------------------------------------------------+
```

- 기본 진입은 프로젝트 작업실 하나로 통합한다. 상단은 프로젝트·현재 임무·활동 수·현재
  확인할 사건만 남긴다. 개요의 중복 지도/제목/설명 패널은 통합 대상이다.
- 현재 임무는 기록된 목표/부모 작업이 있으면 사용한다. 연결 근거가 없으면 개별 작업으로
  표시하고 관찰된 도구들을 임의의 큰 프로젝트 목표로 묶지 않는다.
- 오른쪽은 선택 캐릭터/작업의 고정 상세 패널이다. 하단은 최신 사건 몇 건과 전체 이력 진입이다.
- 모델/추론 설정·터널 상태·호스트 경로는 연결 상세로 이동한다. 출처와 최신성은 작은 표시로 남긴다.
- 오래된 수동 보고·완료 목록·Git 전체 변경·일반 사용 설명은 기록/관리 서랍에 둔다.
  데이터나 필요한 관리 기능을 삭제하는 제안이 아니라 기본 화면의 중복/노출을 줄이는 것이다.
- 승인 요청은 실제 대기 항목이 있을 때 알림으로 연결한다. 기존 승인 링크·폼·검증은 유지한다.
- 폰은 간단한 임무 바 → 지도 → 선택 시 하단 상세 시트 순서다. 긴 설명이 지도보다 앞서지 않는다.
  선택 캐릭터 자동 초점과 목록 보기를 함께 제공하고, 줌·관찰 중지·동작 줄이기는 접근 가능하게 둔다.

## 캐릭터·직업·장비의 의미

실제 객체 identity는 계속 `sourceId + actorId`다. 프로젝트는 활동 공간, 임무는 실제 작업,
캐릭터는 실제 에이전트/세션 또는 호출된 MCP·실행 객체다. 별명·의상·직업은 이 identity의 표시 설정이다.
MCP/실행기를 모두 AI 인격으로 부르지 않고, 도구/지원 객체임을 상세에 밝힌다.

직업은 설계자·개발자·검토자·테스터·운영자처럼 업무 책임이 드러나는 이름을 기본으로 한다.
책/설계도·공구·돋보기·시험 장치·콘솔 같은 실루엣과 작업 동작을 부여한다.
직업 배지는 지속 설정, '지금 하는 행동'은 현재 이벤트로 구분한다. 개발자가 검사한다고
새 인물이 생기거나 직업 자체가 바뀌지는 않는다. 사용자 별명/색상/외형 설정은 실제 모델이나
권한을 바꾸지 않는다. 현재 실행 중인 작업도 소급 변경하지 않는다.

앞선 '사고 역할 별도 캐릭터' 요구는 같은 소유자에 연결된 보조 표현으로 유지할 수 있다.
별도 역할이 켜진 경우 소유자 연결을 표시하고 정원/실행 수를 중복 집계하지 않는다.
미관측 기본 두뇌 카드는 상시 노출에서 제외하는 제안이다. 이 표시 방식 변경은 본 설계의 승인 대상이다.

장비에는 두 종류가 있다. 외형 장비는 의상/도구 모양을 꾸미며, 작업 장비는 현재 연결된
MCP·CLI·실행 프로필을 설명한다. 잠금/미연결은 실제 상태와 일치한다. 작업 장비를 바꾸는
기능은 기존의 등록된 프로필 설정 경로로 연결하며, 외형 교체가 실행 권한을 부여하지 않는다.

## 스킬 발동과 업무 동작

1차는 기존 action/tool_name에 근거한 읽기·편집·검색·검사·실행·검토 동작을 구별한다.
예: 읽기는 책 펼치기, 편집은 공구 작업, 검사는 시험 장치, 검색은 탐색 빛,
검토는 돋보기, 완료는 짧은 정리 동작이다. 도구 수준 신호를 특정 스킬 사용으로 부르지 않는다.

정확한 스킬명은 현재 스키마에 없다. 2차에서 명시적인 skill 식별/표시명과 호출 시작·종료,
실행 소유자·task/call 연결·관측 출처를 선택 필드로 추가한다. 기존 이벤트는 그대로 읽힌다.
수집기는 허용된 식별자만 보존하고 스킬 입력/프롬프트/비공개 추론을 복사하지 않는다.
Claude의 Skill 이름만으로 세부 스킬을 알 수 없고, Codex가 SKILL.md를 읽었다는 사실만으로
실제 발동을 확정하지 않는다. 명시적인 보고는 '보고됨'으로 표시한다.

스킬 발동은 이벤트 ID당 한 번 발생한다. 시작 때 짧은 효과, 실제 작업 중에는 절제된 반복 동작,
종료 때 성공/실패 효과와 결과 연결을 보여준다. 관측이 끊기면 작업 중이라고 계속 연출하지 않는다.
효과를 누르면 그 호출/작업으로 이동한다. 숨김 복귀·과거 재생·중복 조회는 새 발동으로 오인하지 않는다.

## 말 걸기와 디버깅

첫 대화는 선택한 캐릭터의 실제 기록에 답하는 버튼으로 시작한다.
'지금 뭐 해?', '왜 멈췄어?', '마지막 결과는?', '관련 기록 보여줘'는 수집된 상태·시간·결과를
짧게 설명한다. 기록이 부족하면 모른다고 밝힌다. 이 설명에는 추가 모델 호출이 필요 없다.

상세의 기본 순서는 요청/업무 제목 → 담당/현재 행동 → 사용 도구·스킬 → 결과/차단 사실 →
관련 이벤트 → 원문 로그다. 실패 문구와 종료 코드는 근거이며 추정한 근본 원인과 구별한다.
원시 로그는 기존 부모의 인증된 상세 화면에서 열고 지도 프레임으로 통째로 보내지 않는다.

'이 오류 분석해줘', '이어서 작업해줘'는 선택 프로젝트/actor/task와 공개된 결과를 포함한
작업 요청으로 연결한다. 기본 가정은 기존 웹 채팅/에이전트 흐름을 이용하는 것이다.
새 대화 생성·기존 세션 전송 기능이 실제 지원되는지는 별도 연결 검증 전까지 약속하지 않는다.
대시보드 자체 자유 AI 대화는 3차에서 모델·세션·사용량·실행 대상을 분명히 선택하는 별도 기능이다.

예시: 테스트 동작 시작 → 실패 표시 → 캐릭터 선택 → 어떤 테스트의 어떤 단계가 실패했는지와
종료 코드 확인 → 원문 로그 열기 → 그 작업에 연결된 분석 요청. 동일 입력의 재실행은 명시적으로
요청할 때 기존 실행/승인 경로를 사용하며, 실패 애니메이션이 자동 재시도를 시작하지 않는다.

## 구현 순서와 완료 기준

1차: 화면 단순화 + 캐릭터 상세/기록 기반 대화 + 직업 표시 + 기존 이벤트의 작업 동작.
- 1440x900 첫 화면에 임무, 지도와 주요 상세 진입이 함께 보인다.
- 390x844에서 긴 보고/설명 없이 지도가 보이고, 터치 한 번으로 선택 작업 요약이 열린다.
- 현재 임무/캐릭터/결과/로그로 이어지는 관계를 유지하고 서로 다른 범위의 카운트를 혼동시키지 않는다.
- 오래된 실패와 현재 차단을 구별한다. 데이터가 없으면 해결됨/진행 중이라고 단정하지 않는다.
- 기존 로그인·프로젝트 전환·승인 링크·출력 확인·6명 정원/오래된 호출 교체·접근성을 보존한다.

2차: 스킬 이벤트 수집·검증 + 스킬별 발동/완료 효과 + 재현 가능한 타임라인.
- Claude/Codex/ChatGPT별 실제 수집 경로와 '보고' 경로를 각각 검증한다.
- 동일 호출은 한 번만 발동하고 정확한 owner/task와 연결된다. 미수집 스킬을 추측하지 않는다.

3차: 캐릭터 설정 저장 + 실제 작업 장비 변경 + 요청한 대화 범위 연결.
- 외형/직업 표시 설정과 실제 에이전트 프로필·도구·권한 변경을 분명히 구분한다.
- 새 대화/작업 전달 경로는 실제 호출 성공과 대상/비용/권한 경계 검증 후 제공한다.

회귀 검증은 각 단계에서 변경한 모델·브리지·실제 브라우저 흐름을 대상으로 한다.
접근성/키보드, 동작 줄이기, 숨김 복귀, 다중 세션 identity, 7명 이상,
실패·취소·결과 불명, 320/390px, 잘린/중복/순서 역전 이벤트를 포함한다.
검토 단계인 이번 문서 작성을 위해 기존 전체 테스트/배포를 반복하지 않는다.
