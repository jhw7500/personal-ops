# MCP 승인·등록 단순화 설계 검토

검토일: 2026-10-24. 대상: [설계안](../superpowers/specs/2026-10-24-mcp-trusted-development-design.md).

결론: 독립 architect 검토의 세 지적을 수정했고, 재검토에서 모두 해소됐음을 확인했다. 남은 중대 모순이나 이번 준비에 필요한 새 사용자 결정 사항은 발견되지 않았다. **설계 검토 결과이며, 기능 구현·운영 적용·동적 테스트 통과를 뜻하지 않는다.**

## 지적과 반영

| 최초 지적 | 중요도 | 반영한 계약 | 재검토 |
| --- | --- | --- | --- |
| v2 철회/손상 후 v1 파일이나 구버전 rollback으로 과거 권한이 살아날 수 있음 | P1 | 영속 전환 표식, v1 fallback 금지, 기존 grant·카드 무효화, callback revision, 시작/전환 직렬화, runtime ABI 3 및 admission floor | 해소 |
| 장기 grant만으로 Git-ignored QA 결과의 필드별 등록 문제가 해결되지 않음 | P1 | 소유자가 정한 디렉터리의 `text` 읽기를 Workspace policy v2에 포함. 기존 `json_fields`, 민감 경로 검사, namespace 중첩 금지와 읽기 상한 보존 | 해소 |
| OS 계정 권한 확대 전체를 자동 감지하는 것으로 오해할 수 있음 | P2 | 관리되는 capability/감지 대상 바인딩과 외부 sudoers·ACL·자격증명 변화를 구분. 동일 UID 임의 실행의 실제 신뢰 범위를 표시 | 해소 |

세 수정 모두 필수 회귀 검증 사례에 반영했다. 재검토는 위 세 항목과 남은 중대 모순에 한정한 읽기 전용 검토였다.

## 구현할 때 확인할 사항

- `until_revoked`는 제안된 기본안이다. 기존 권한의 자동 승격이나 사용자 대신 영구 권한을 발급하는 근거로 사용하지 않는다.
- nullable 만료의 모든 소비자, 철회/시작 경합, 상태 전환 중 실패, 옛 callback, 구버전 rollback을 실제 검사로 증명해야 한다.
- 일반 명령 10회에서 추가 접근 카드·작업별 profile·refresh가 발생하지 않는지 실제 웹 연결에서 측정해야 한다. ChatGPT 자체의 도구 확인은 따로 기록한다.
- policy v2의 디렉터리 읽기는 기존 제한된 실험 산출물의 범위를 자동 확대하지 않는다.
- 새 PC의 runtime·터널·키·grant는 별도로 준비한다. 소스 묶음의 정적 검증을 WSL 설치 성공으로 표현하지 않는다.

## 수행한 검증과 범위

설계 문서 및 관련 구현 계약을 읽고 독립 검토와 수정 후 재검토를 수행했다. 설계 작성 중 제품 코드, 운영 정책, grant 또는 서비스를 변경하지 않았다. 기능 테스트·브라우저 검증·PIM 타겟 테스트는 수행하지 않았다.

함께 준비한 기존 소스 이관본은 별도 검증기로 압축 멤버 안전성, 파일 해시, runtime/control inventory digest, Python AST 및 JSON 문법을 검증했다. 고유 소스 257개, runtime 109개, control 143개가 일치했다. 그 증거는 이관 묶음의 `SOURCE-STATIC-VERIFICATION.json`에 있다.
