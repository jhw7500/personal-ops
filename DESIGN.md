## Design principles
One actor per stable source/object, one work item per operation. Execution state is distinct from acknowledgement of an MCP call. Current owner state observations override older event-only lifecycle state for the same host operation; event metadata and honest provenance remain available. Successful observation time is distinct from task transition time.
Partial fetch failures preserve last good data, show degraded/stale state, and never report known completion as current activity. No progress percentage or ETA is invented.
The brain represents an agent's reasoning/model capability rather than a second worker counted in activity. An unobserved ChatGPT role is an explanatory placeholder, never a synthetic task or live session. Host Codex's generic code action does not prove editing or reasoning; its unsupplied detail is explicitly identified. A role-flow guide is separate from recorded causal links, which require actual parentTaskId references.
Known detailed host-agent records retain their title, recorded parent and fresh action instead of being replaced by a generic host poll. A fresh process observation cannot revive an expired reasoning/action signal. Only fresh known active work uses present-tense verbs; queued/prepared, unknown, paused/stale and completed work have distinct wording. Prepared plans remain ahead of completed history on the work board. Manual motion pause also stops brain-icon effects.
The map has a dedicated thinking-role station with one keyed presentation character per known agent and a neutral ChatGPT role when no ChatGPT actor is known. A thinker links to its real owner; agent/task totals remain unchanged. Model configuration and generic host activity do not prove thought activity. Fresh directly observed reason signals alone drive the thinking gesture; reported-only reasoning, missing signals, stale reads, observation pause and idle all remain distinct. Placeholder selection explains the unobserved role rather than inventing an owner or task. Project changes discard old role views. Concurrent active reason work remains visible even when the executor is displaying a newer code task. Brain, role and role detail use the selected work's own telemetry, preventing cross-task model/token attribution. Static placeholders do not sustain animation loops; selected roles remain visible in the phone camera. The thinking station renders below actors crossing the hall so they remain clickable.

## Visual language
Reuse dark background/panel/line/muted/accent variables and existing pixel assets. Use compact cards, aligned status text and whitespace for hierarchy. Use teal for observed success/connection, amber for pending/expiry, and existing error colors for failures. Avoid new color/token systems.

Details lead with who/what/status and named recorded connections; keep provenance/model/token fields and raw identifiers available in technical details. The role station stays within the scrollable map, preserving existing room and execution movement geometry.

## Accessibility
Keep keyboard-operable navigation and visible focus; apply correct selected/tab/panel semantics where used. Loading/errors are readable status messages. Status is never conveyed only through color or movement. Preserve reduced-motion and map motion pause. New controls have meaningful labels and comfortable phone targets.

## Responsive behavior
Existing 760px breakpoint remains the starting point. On phone, navigation may scroll inside its own region; cards stack, long selectors and IDs shrink/wrap, and forms never widen the document. The workroom can scroll internally while surrounding page stays within viewport.

## Interaction states

Show initial loading, valid empty state, successful observation age, partial error, disconnected, inactive/expired/revoked grant, and execution lifecycle honestly. Avoid selection/focus resets on background refresh; discard old-project replies. Hidden pages and paused following respect existing polling policies.

Internal reasoning and unobserved remote MCP calls are not synthesized. Advanced approval explanations remain available with their existing scope disclosures.

## Stage 6 called-character lifecycle

The owner explicitly requests that only actually invoked characters appear. A registration, configured model, idle CLI, or an unobserved seeded object is not a call. New calls enter through the entrance in call order, perform the observed work, then return to the waiting room. Completed called Codex and role characters now remain waiting; this supersedes Stage 4's disappear-on-success policy. Initial completed history may establish called status and waiting presence, but must not play invented live work.

Each room has six visible occupants, including role views. At capacity, the character whose actual call was observed longest ago leaves through the door, corridor and entrance; the newcomer replaces it after space is available. Heartbeats, completion, selection, list order and routine polling do not refresh call age. An evicted invocation remains offscreen until a genuinely new call; selection can inspect its work without admitting it again. All actual work and canonical counts remain recorded, including work whose character is offscreen. This visual eviction never cancels an execution.

Retain the same character identity across work and waiting, show failed work in the recorded attention list, and do not turn an unconfirmed outcome into completion. Preserve one owner's distinct observed roles and concurrent calls without inventing additional workers. Keep pause, hidden-tab behavior, project reset, selection, reduced motion and the Stage 5 opaque-frame boundary. New arrivals are staggered; pending characters wait outside the rendered map, and physical entry cannot overfill a room while the previous occupant exits.

Verify no never-called characters; actual-call ordering independent of actor names and heartbeat time; completed agent/role return to waiting; seventh and later calls replace the oldest without reappearance loops; room occupancy never exceeds six; all tasks remain inspectable; reduced motion, pause, project switching and 390/320px remain usable.
