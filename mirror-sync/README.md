# mirror-sync

`github.com/jhw7500/*` → `192.168.10.2:31406/hwjo/*` **큐레이션 미러**를 싱크하는 수동 CLI.
personal-ops 이슈 #34.

미러는 upstream 의 부분집합이 아니라 **의도적으로 다른 사본**이다. 내부 계획문서 참조·GitHub PR
번호·보드 원시 캡처를 걷어낸 상태이므로, upstream 파일을 그대로 복사하면 그 제거분이 되살아나거나
반대로 미러 고유 서술이 사라진다. 이 스크립트는 그 "그대로 복사"를 하지 않는 것이 존재 이유다.

## 왜 만들었나

2026-09-04 에 max9296 을 세 번 싱크하면서 **실제로 큐레이션을 잃었다.**
`docs/360p-readout-120fps-validation.md` 를 통째로 덮어쓰다 미러 전용 "증적 위치" 문단(원시 캡처를
저장소에 두지 않는 정책을 설명하는 부분)이 지워졌고, `git diff` 의 삭제된 줄을 뒤져서야 발견했다.

**조용히 실패하는 종류다.** 복사는 성공하고 테스트도 통과하며, diff 를 일부러 읽지 않으면 드러나지
않는다. 그래서 이 모듈의 중심은 복사 로직이 아니라 **어서션**이다 (아래 [어서션 6종](#어서션-6종)).

## 4분류 축

upstream 의 `--from..--to` 변경 파일을 네 갈래로 나눈다. 분류는 `config/curation/<base>.conf` 의
다섯 축이 결정하고, 우선순위는 `UPSTREAM_ONLY > MIRROR_ONLY > KEEP_MIRROR > (그 외) 복사` 다.

| 분류 | conf 축 | 스크립트 동작 | 이 축이 없으면 |
|---|---|---|---|
| **복사** | (어느 축에도 안 걸린 나머지) | 미러에 그대로 쓴다. upstream 에서 삭제됐으면 미러에서도 지운다 | — (기본 동작) |
| **보존** | `KEEP_MIRROR` | **덮어쓰지 않는다.** 표 아래 "수동 이식 필요" 블록에 다시 모아 출력 | 양쪽이 의도적으로 다른 파일이 upstream 판으로 덮여 미러 고유 서술이 사라진다 — **2026-09-04 사고가 정확히 이것** |
| **미반입** | `UPSTREAM_ONLY` | 미러로 넘기지 않는다 | 내부 계획문서·GitHub Actions·보드 원시 캡처가 공개 미러로 새어나간다 |
| **미삭제** | `MIRROR_ONLY` | upstream 에 없다고 미러에서 지우지 않는다 | 미러에만 있는 파일이 "upstream 에 없음 = 삭제됨"으로 오인돼 사라진다 |

나머지 두 축(`FORBID`, `MUST_SURVIVE`)은 분류가 아니라 **싱크 결과를 사후 검사하는 문자열**이다.
분류 규칙이 맞더라도 파일 내용에 금지 문자열이 섞여 들어오거나 필수 문단이 사라질 수 있어서, 경로
단위 분류와 별개로 내용 단위 검사가 필요하다.

축이 하나라도 빈 배열이면 스크립트는 **종료 코드 2 로 거부한다.** 빈 축은 에러 없이 "미반입 0건 /
보존 0건"을 출력하며 전량 복사로 흘러가는데, 그것이 이슈 #34 가 지적한 실패 방식 그 자체다.

**축은 반드시 bash 배열이어야 한다.** 스크립트가 conf 를 source 하기 전에 다섯 축을 `unset` 하고,
source 직후 `declare -p` 로 **선언 타입**을 확인해 배열이 아니면 종료 코드 2 로 거부한다. 길이만
보면 부족하다 — 이슈 #34 본문의 예시 문법인 `KEEP_MIRROR="a b c"` 는 항목 1개짜리 축이 되어
`${#KEEP_MIRROR[@]} == 1` 로 길이 검사를 통과하고, 그 1개 항목("a b c" 전체)은 어떤 경로와도
매칭하지 않는다. 즉 다섯 축이 전부 죽은 채로 전량 복사가 일어나면서 에러도 경고도 나오지 않는다.

경로 매칭 규칙(`**`→`/` 포함 임의 문자열, `*`→`/` 를 넘지 않는 임의 문자열, `?`→`/` 아닌 한 글자,
나머지는 전부 리터럴, 패턴은 경로 전체에 앵커)은 `config/curation/max9296.conf` 상단 주석과
스크립트의 `glob_to_ere()` 가 문자 그대로 같다. 디렉터리 전체를 지정하려면 반드시 `artifacts/**`
처럼 `/**` 를 붙인다.

경로 축의 패턴이 **upstream `--to` 트리와 미러 인덱스 어느 쪽과도 매칭하지 않으면 `[주의]` 로
알린다.** 한 글자 오타(`artifacts/**` → `artifact/**`)는 에러를 내지 않고 그 패턴만 조용히 죽이며,
그 축이 덮던 파일들이 기본값(복사)으로 흘러간다. 실측: 그 오타 하나로 `미반입 278 → 42`,
`복사 58 → 294` 가 되고 보드 원시 캡처 236개가 복사 대상이 된다.

## 어서션 6종

`--apply` 는 파일을 복사·삭제하고 `git add -A` 를 마친 뒤 **미러 인덱스**를 대상으로 여섯 가지를
검사한다. 인덱스를 보므로 방금 새로 복사된 파일도 검사 범위에 들어간다.
하나라도 실패하면 **커밋하지 않고 종료 코드 4** 로 끝난다. 경고로 넘기지 않는다.

| 어서션 | 무엇을 막는가 | 오라클 |
|---|---|---|
| `ASSERT_A_UPSTREAM_ONLY_INFLOW` | 반입 금지 파일이 미러에 생기는 것 | `UPSTREAM_ONLY` 패턴 |
| `ASSERT_B_FORBID_INFLOW` | 금지 **문자열**이 미러 추적 파일에 나타나는 것 — 파일 경로는 통과했지만 본문에 `docs/superpowers/`·`PR #`·`pull/` 같은 내부 참조가 섞여 온 경우 | `FORBID` 문자열 |
| `ASSERT_C_MUST_SURVIVE_LOST` | 미러에 반드시 남아야 하는 문자열이 사라지는 것. **이슈 #34 사고를 직접 막는 어서션** | `MUST_SURVIVE` (+ `MUST_SURVIVE_IN` 으로 파일 구속) |
| `ASSERT_D_MIRROR_ONLY_DELETED` | 미러 전용 파일이 사라지는 것 | `MIRROR_ONLY` 패턴 |
| `ASSERT_E_STAGED_AS_REPORTED` | "쓰기" 로 **보고한 것과 커밋에 들어간 것이 다른** 상태 | upstream 트리의 blob sha·모드 (규칙과 무관) |
| `ASSERT_F_NEW_FILE_INFLOW` | 미러에 **없던 파일**이 사람의 승인 없이 새로 들어오는 것 | 복사 전 미러 인덱스 실측 (규칙과 무관) |

### A~D 는 규칙을 검사하고, E~F 는 규칙 바깥을 검사한다

`ASSERT_A` 는 분류(`classify_path`)가 쓰는 것과 **같은** `UPSTREAM_ONLY` 패턴으로 인덱스를 본다.
따라서 "어느 패턴에도 걸리지 않아 **기본값인 복사**로 흘러간 경로"는 구조적으로 잡을 수 없다.
미러는 upstream 341개 중 65개만 담은 부분집합이므로 그 기본값이 틀린 경우가 다수다 — 새로 생긴
내부 워크로그 한 장이 공개 미러로 새어나가는 경로가 정확히 여기다.

`ASSERT_F` 는 그 구멍을 패턴이 아니라 **미러 인덱스 실측**으로 막는다. 이번 싱크로 미러에 새로
들어오는 파일이 하나라도 있으면 목록을 출력하고 `--allow-new` 없이는 커밋하지 않는다. dry-run 도
같은 목록을 "신규 반입" 블록으로 보여주므로, `--apply` 전에 눈으로 확인하는 것이 정상 흐름이다.

`ASSERT_E` 는 "보고했는데 커밋에는 없다"를 막는다. `git add -A` 가 보고와 다르게 동작하는 경로가
실재한다 — 미러 `.gitignore` 에 걸리는 새 파일은 스테이징하지 않고(아래 게이트가 먼저 막는다),
`skip-worktree` 가 걸린 추적 파일은 **종료 코드 0 인 채로 변경을 통째로 무시한다**. 둘 다 화면에는
`쓰기 <경로>` 와 `[PASS]` 와 "커밋 완료" 가 나오고 커밋에는 그 변경이 없다. E 는 존재 여부가
아니라 인덱스의 **blob sha 와 모드**를 upstream `--to` 트리와 대조한다.

### 미러 .gitignore 와 부딪히는 복사 대상은 쓰기 전에 거부한다

복사 대상이 미러의 `.gitignore` 에 걸리면 `git add -A` 가 조용히 건너뛴다. 그 파일은 커밋되지 않은
채 미러 디스크에 남고, 무시 파일이라 `git status --porcelain` 에도 안 잡혀 **다음 `--apply` 의
clean 검사까지 통과하며**, 안내하는 복구 명령(`clean -fd`, `-x` 없음)으로도 지워지지 않는다.
그래서 `git check-ignore` 로 **한 파일도 쓰기 전에** 찾아내 종료 코드 3 으로 거부한다(dry-run 은
같은 목록을 `[주의]` 로 미리 보여준다). 미러에 두지 않을 파일이면 `UPSTREAM_ONLY` 에 추가하고,
두어야 할 파일이면 미러의 `.gitignore` 를 먼저 손본다.

### `ASSERT_C` 는 문자열을 파일에 못박는다

`MUST_SURVIVE_IN` 은 `MUST_SURVIVE` 와 **같은 길이의 병렬 배열**이고, i 번째 원소가 `MUST_SURVIVE[i]`
가 살아 있어야 할 경로다(빈 문자열이면 저장소 전체). 저장소 전체 검사만 하면 같은 문구가 다른
파일에 우연히 생겼을 때 정작 그 문단이 지워져도 통과한다 — 이 축이 지키는 것은 "문구의 존재"가
아니라 "그 파일의 미러 고유 서술"이므로 파일에 못박는다.

max9296 conf 는 `KEEP_MIRROR` **6개 전부**에 문자열을 하나씩 대응시켰다. `KEEP_MIRROR` 의 보존은
"복사하지 않는다"로만 구현돼 있어서, 목록에서 한 줄이 빠지거나 경로가 바뀌어 매칭에 실패하는
순간 upstream 판이 미러 판을 덮어써도 나머지 어서션이 전부 통과한다 — 2026-09-04 사고와 같은
모양이다. 6개 문자열은 전부 **미러 판에만 있고 upstream 판에는 없는** 문장으로 골랐다
(2026-09-04 실측: upstream 전체 매치 0건, 미러 1건).

### 왜 사람 체크리스트가 아니라 어서션인가

이슈 #34 가 이 점을 못박았고, 여기 다시 적어 둔다.

사고 당시 실패 신호가 **하나도 없었다.** 복사는 성공했고, 테스트도 통과했고, 명령은 0 으로
끝났다. 잃어버린 문단은 `git diff` 의 삭제된 줄을 일부러 뒤져서야 나왔다. 이런 실패에 대해
체크리스트는 두 가지를 동시에 요구한다 — 사람이 (1) 체크리스트를 돌릴 것을 기억하고 (2) 수백 줄
diff 를 실제로 끝까지 읽을 것. 같은 날 세 번의 싱크에서 사람은 계속 자리에 있었고, 그럼에도
놓쳤다.

어서션은 **기본 결과를 뒤집는다.** 체크리스트에서 기본값은 "아무도 안 봤으니 그대로 나간다"이고,
어서션에서 기본값은 "확인되지 않았으니 멈춘다"다. 검사가 통과해야 커밋이 만들어지므로, 사람이
diff 를 읽지 않아도 손실은 커밋에 도달하지 못한다.

### 적용 실패 시 워킹트리

**자동 롤백하지 않고 복사·스테이징된 상태 그대로 남긴다.** 어서션이 잡아내는 것이 "조용히 사라진
큐레이션"이라 사람이 `git diff --cached` 로 무엇이 유입·소실됐는지 직접 봐야 하는데, 자동 청소는
그 증거를 지운다.

되돌릴 수 없는 상태가 아니다: `--apply` 는 시작 전에 미러 워킹트리가 clean 한지 확인하고 아니면
거부하므로 직전 상태는 정확히 `HEAD` 다. 복구는 항상 아래 한 줄이다.

```bash
git -C <mirror> reset --hard HEAD && git -C <mirror> clean -fd
```

이 안내는 **적용 단계에서 0 이 아닌 코드로 끝나는 모든 경로**에서 출력한다 — 어서션 실패(4)뿐
아니라 복사 도중 실패(5)와 예기치 못한 중단까지 포함한다(EXIT 트랩). 반쯤 적용된 상태를 안내
없이 남기면 다음 `--apply` 가 그것을 "남의 변경"으로 오귀속하고, 사람이 그 안내를 따라 커밋하면
큐레이션 검사를 한 번도 통과하지 않은 싱크가 미러에 들어간다. 그래서 dirty 거부 메시지에도
"직전 실행이 적용 도중 실패해 남긴 것일 수도 있다"는 단서를 함께 낸다.

확인 가능한 실패는 **한 파일도 쓰기 전에** 끝낸다: 지원하지 않는 파일 모드(심볼릭 링크·서브모듈),
`.gitignore` 충돌, 뒤집힌 범위가 전부 사전 검사 대상이다. 그래서 남는 잔여물 자체가 드물다.
삭제는 쓰기보다 **먼저** 수행한다 — upstream 이 파일을 같은 이름의 디렉터리로 바꾼 정상적인
변경에서, 삭제가 뒤에 오면 `mkdir` 이 아직 남아 있는 그 파일과 부딪힌다.

## push 는 자동화하지 않는다

**이 스크립트가 자동으로 하는 최대 범위는 미러 저장소의 로컬 커밋이다. 원격 push 는 반드시 사람이
직접 승인하고 직접 실행한다.**

`--push` 플래그도, push 하는 서브커맨드도 **의도적으로 두지 않았다.** 빠뜨린 기능이 아니다.
실수로 붙이는 것을 막기 위해 `--push` 를 주면 인식만 하고 **종료 코드 1 로 거부**한다.

근거는 되돌리는 비용의 비대칭이다. 로컬 커밋은 `git reset` 한 줄이면 없던 일이 되고 아무도 보지
못한다. push 는 다른 사람·CI·미러가 즉시 보게 되는 **외부 공개 행위**이고, 되돌리려면 강제 push
와 그것을 이미 받아간 쪽들의 정리까지 따라온다 — 공개된 순간 비용이 급격히 커진다. 게다가 이
스크립트가 다루는 것은 "무엇을 공개 미러에 내보내지 않을 것인가"이므로, 잘못 나간 한 번이 곧
이 모듈이 막으려는 사고다.

**이 원칙은 mirror-sync 뿐 아니라 personal-ops 자동화 전반에 적용한다** — 자동화는 로컬에서
되돌릴 수 있는 지점까지만 하고, 외부에 공개되는 마지막 한 걸음은 사람이 밟는다.

## 사용법

```
mirror-sync.sh --pair <base> --from <sha> --to <sha>            # dry-run (기본, 순수 읽기)
mirror-sync.sh --pair <base> --from <sha> --to <sha> --apply    # 복사 + 어서션 + 미러 로컬 커밋
mirror-sync.sh --help
```

| 옵션 | 의미 |
|---|---|
| `--pair <base>` | (필수) `config/pairs.tsv` 의 base 값이자 `config/curation/<base>.conf` 파일명 |
| `--from <sha>` | (필수) **upstream 저장소**의 시작 커밋. 이 커밋은 범위에 포함되지 않는다 |
| `--to <sha>` | (필수) **upstream 저장소**의 끝 커밋. 복사할 내용을 이 커밋 트리에서 읽는다 |
| `--apply` | 실제 적용. 없으면 dry-run 이며 **어떤 파일도 쓰지 않는다** |
| `--allow-new` | 미러에 **없던 파일**이 새로 들어오는 것을 승인한다. 없으면 `--apply` 가 `ASSERT_F` 로 거부한다 (dry-run 에는 영향 없음) |
| `-h`, `--help` | 도움말 출력 후 종료 |

`--from` / `--to` 는 sha 뿐 아니라 `HEAD~12`·브랜치명 등 임의 refspec 을 받는다
(`rev-parse --verify "<ref>^{commit}"` 로 해석). **`--from` 은 `--to` 의 조상이어야 한다.**
아니면 diff 방향이 뒤집혀 upstream 의 '추가'가 '삭제'로 나오고 미러에 정상적으로 있는 파일들이
실제로 지워지므로, `--apply` 는 종료 코드 3 으로 거부한다(dry-run 은 `[주의]` 로 경고만 한다).

대상 저장소는 `pairs.tsv` 가 지정한 곳으로 **고정된다.** 스크립트 진입부에서 `GIT_DIR` ·
`GIT_WORK_TREE` 등 주변 git 환경변수를 `unset` 하고(git 훅 · `git rebase --exec` · `git bisect run`
안에서 실행하면 `git -C` 가 무시된다), 각 경로의 워크트리 최상위가 설정 경로와 정확히 같은지
확인한다(아니면 종료 코드 3). 최상위 검사가 없으면 미러 클론의 `.git` 이 사라졌을 때 `git add -A`
가 **상위 저장소 전체**를 스테이징해 엉뚱한 곳에 싱크 커밋을 만든다.

환경변수 `MIRROR_SYNC_CONFIG_DIR` 로 설정 디렉터리를 재지정할 수 있다(기본 `<모듈>/config`).
테스트가 mock 저장소를 가리킬 때 쓰는 유일한 주입점이다.

### 실제 흐름 — dry-run → 수동 이식 → --apply → 사람이 push

**1) dry-run 으로 4분류를 확인한다.** 아무것도 쓰지 않는다.

```bash
mirror-sync.sh --pair max9296 --from HEAD~12 --to HEAD
```

아래는 2026-09-04 에 실제로 실행한 출력이다. 표 본문의 일부 줄을 `...` 로 생략했고(복사 10줄 중 8줄,
미반입 17줄 중 15줄 — 대부분 `.github/workflows/*`), 합계와 나머지는 실제 값 그대로다.

```
mirror-sync — 큐레이션 미러 싱크
  쌍       : max9296
  upstream : /home/jhw/ai/opencode/projects/max9296 (master)
  mirror   : /home/jhw/ai/opencode/projects/max9296-gitlab (main)
  범위     : b67e19d .. 4fa9881  (upstream 커밋)
  모드     : dry-run — 아무 파일도 쓰지 않는다

분류 표 — upstream 변경 파일 29개
  분류    동작      상태  경로
  ------  --------  ----  --------------------------------------------------
  복사    쓰기      M     CHANGELOG.md
  복사    쓰기      M     max9296.c
  ...
  보존    수동이식  A     README.md
  보존    수동이식  M     docs/360p-readout-120fps-validation.md
  미반입  건너뜀    M     .github/workflows/claude.yml
  ...
  미반입  건너뜀    M     docs/v4l2-controls-guide.md
  미삭제  보호      -     docs/pim-package-binary.md
  ------  --------  ----  --------------------------------------------------
  합계: 복사 10 (쓰기 10 / 삭제 0)
        보존 2 · 미반입 17 · 미삭제 1

===============================================================================
 수동 이식 필요 — KEEP_MIRROR 2개
-------------------------------------------------------------------------------
   [A] README.md
       git -C /home/jhw/ai/opencode/projects/max9296 diff b67e19d 4fa9881 -- "README.md"
   [M] docs/360p-readout-120fps-validation.md
       git -C /home/jhw/ai/opencode/projects/max9296 diff b67e19d 4fa9881 -- "docs/360p-readout-120fps-validation.md"
===============================================================================
```

3열 "상태"는 upstream diff 의 `A`/`M`/`D`/`T` 이고, 정보성 미삭제 행은 `-` 다.

합계의 `삭제 N` 은 **실제로 지우는 건수**다. upstream 에서 지워졌지만 미러에 애초에 없어서 아무것도
하지 않는 행은 `삭제생략` 으로 따로 세고, 있을 때만 `(쓰기 W / 삭제 D / 삭제생략 S)` 처럼 덧붙는다.
300줄짜리 표를 건너뛰고 합계만 읽는 사람에게 "미러에서 파일이 지워진다"로 읽히면 안 되기 때문이다.
커밋 본문도 같은 값을 쓴다.

미러에 **없던 파일**이 새로 들어오면 표 아래에 "신규 반입" 블록이 따로 나온다. 그 목록이 곧
`--apply` 에 `--allow-new` 가 필요한 이유이고, 공개 미러로 내부 문서가 새어나가는 경로다.

**2) "보존" 파일을 수동 이식한다.** 블록에 출력된 `git diff` 명령을 그대로 붙여 upstream 변경분을
읽고, 미러 고유 서술을 유지한 채 필요한 부분만 손으로 옮긴다. **이 단계를 건너뛰면 upstream 의
변경이 미러에 영영 반영되지 않는다** — 스크립트는 이 파일들을 절대 건드리지 않기 때문이다.

이식한 결과는 `--apply` 전에 커밋해 두거나(미러가 dirty 하면 `--apply` 가 거부한다), 아니면
`--apply` 를 먼저 돌려 싱크 커밋을 만든 뒤 별도 커밋으로 이식한다. 어느 쪽이든 이식분과 자동
복사분이 한 커밋에 섞이지 않는 편이 나중에 읽기 쉽다.

**3) `--apply` 로 적용한다.** 복사 → 어서션 → 미러 **로컬 커밋**까지다.

```bash
mirror-sync.sh --pair max9296 --from HEAD~12 --to HEAD --apply
mirror-sync.sh --pair max9296 --from HEAD~12 --to HEAD --apply --allow-new   # 신규 반입이 있을 때
```

시작 전에 미러가 `pairs.tsv` 의 `mirror_branch` 를 체크아웃한 상태이고 워킹트리가 clean 해야
한다(아니면 종료 코드 3). dry-run 의 "신규 반입" 블록에 파일이 있었다면 그 목록을 확인한 뒤
`--allow-new` 를 붙인다 — 없으면 `ASSERT_F` 가 종료 코드 4 로 거부한다.
어서션이 통과하면 아래 형식으로 커밋한다.

```
chore: sync curated mirror — upstream <from_short>..<to_short>
```

본문에는 범위·4분류 합계·통과한 어서션 6종 이름·신규 반입 목록·수동 이식 대기 `KEEP_MIRROR`
목록이 들어간다. 스테이지된 변경이 없으면 커밋을 생략하고 0 으로 끝난다.

**4) 사람이 확인하고 push 한다.** 스크립트는 여기까지 오지 않는다.

```bash
git -C /home/jhw/ai/opencode/projects/max9296-gitlab log -1 -p   # 내용 확인
git -C /home/jhw/ai/opencode/projects/max9296-gitlab push        # 사람이 직접
```

## 파일 구조

|---|---|
| `bin/mirror-sync.sh` | **본체**. 분류 · dry-run 출력 · 복사 · 어서션 · 미러 로컬 커밋 (push 없음) |
| `config/pairs.tsv` | **대상 쌍 단일 소스**. 탭 7컬럼 (base / github remote / gitlab remote / upstream 경로 / mirror 경로 / upstream 브랜치 / mirror 브랜치) |
| `config/curation/<base>.conf` | 쌍별 큐레이션 규칙. 다섯 축을 **bash 배열**로 정의하고 `bin/mirror-sync.sh` 가 source 한다 (선택 축 `MUST_SURVIVE_IN` 포함). 현재 `max9296` · `gstApp` · `imx-vpu` · `sc16is7xx` 4장 |
| `tests/mirror-sync-test.sh` | mock git 저장소 기반 테스트. 어서션 6종이 **되돌리면 실패하는지**까지 확인하고, 실제 쌍이 있는 호스트에서는 배포 conf 를 dry-run 으로 스모크한다 |
| `install.sh` | `~/.local/bin` 심링크 + 실행 비트. 재실행 안전 |

축을 "공백 구분 문자열"이 아니라 **bash 배열**로 둔 이유는 max9296 에 공백·괄호·`&`·`=` 가 들어간
경로가 실제로 3개 있기 때문이다. 문자열로 두면 단어 분할로 조각나 매칭에서 **에러 없이** 빠진다.
자세한 근거는 `config/curation/max9296.conf` 상단 주석에 있다.

## 설치

데몬이 아니라 수동 CLI이므로 systemd 유닛도 타이머도 없다. 설치되는 것은 심링크 하나다.

```bash
./install.sh     # ~/.local/bin/mirror-sync.sh -> bin/mirror-sync.sh (+ 실행 비트)
```

설정 파일은 심링크하지 않는다. `bin/mirror-sync.sh` 가 `readlink -f` 로 자기 실체 경로를 풀어
모듈의 `config/` 를 직접 읽으므로, 심링크로 실행해도 **정본은 항상 이 디렉터리 한 곳**이다.
제거는 `rm ~/.local/bin/mirror-sync.sh` 한 줄이라 `uninstall.sh` 를 따로 두지 않았다.

설치 없이 절대 경로로 바로 실행해도 동작한다.

## 새 쌍 추가

1. **실측부터 한다.** upstream/mirror 양쪽을 `git ls-tree -r --name-only HEAD` 로 뽑아 비교하고,
   공통 파일 중 blob sha 가 다른 것(→ `KEEP_MIRROR`), upstream 에만 있는 것(→ `UPSTREAM_ONLY`),
   미러에만 있는 것(→ `MIRROR_ONLY`)을 가른다. 추측으로 채우지 않는다.
2. `config/curation/<base>.conf` 를 만들고 다섯 축을 **전부** 채운다. 하나라도 비거나 배열이
   아니면 스크립트가 종료 코드 2 로 거부한다. `max9296.conf` 를 형식 참고용으로 복사해 쓰되
   항목마다 근거 주석을 남긴다.
   **`KEEP_MIRROR` 항목마다 `MUST_SURVIVE` 또는 `FORBID` 중 하나로 반드시 앵커한다.**
   `KEEP_MIRROR` 의 보존은 "복사하지 않는다"로만 구현돼 있어 목록에서 한 줄이 빠지면 아무
   어서션도 울지 않는다. 기본은 그 파일의 미러 전용 문장 하나를 `MUST_SURVIVE` 에
   대응시키고 `MUST_SURVIVE_IN` 으로 경로를 묶는 것이다. 고른 문장이 정말 미러 전용인지
   (= upstream 판에는 0건인지) `git show HEAD:<path> | grep -Fc` 로 양쪽을 확인한다.
   **미러 판이 upstream 판의 진부분집합이면 그 방법을 쓸 수 없다** — 미러에만 있는 문장이
   원리적으로 없어서 무엇을 넣어도 첫 실행부터 `ASSERT_C` 가 빨개진다(2026-09-05 실측: 4쌍의
   `KEEP_MIRROR` 15개 중 3개가 이 경우다). 그때는 반대로 **upstream 판에만 있고 미러에 0건인
   문자열**을 `FORBID` 에 넣어 "덮이면 그 문자열이 나타난다"를 `ASSERT_B` 로 잡는다.
3. `config/pairs.tsv` 의 해당 행 주석을 풀고 로컬 클론 절대 경로와 양쪽 브랜치명을 채운다.
   (upstream 과 mirror 의 브랜치 이름은 서로 다를 수 있다 — max9296 은 `master` / `main`.)
4. `UPSTREAM_ONLY` 패턴이 upstream 전용 파일을 **빠짐없이** 덮는지, 그리고 미러 파일을 **오매치하지
   않는지** 확인한다. 어느 쪽이 틀려도 조용히 실패한다.
5. dry-run 을 먼저 돌려 4분류를 눈으로 확인한 뒤에만 `--apply` 로 넘어간다.

사용 가능한 4쌍은 전부 upstream `master` → mirror `main` 이다. 네 쌍 모두 전 범위 dry-run
(`--from <root 커밋> --to master`)이 **종료 코드 0 · 죽은 패턴 경고 0 · 신규 반입 0** 이다
(2026-09-05 실측, 아래 기준값 표).

`pairs.tsv` 의 `upstream_branch` 는 표시용이다. `--apply` 가 실제로 검사하는 것은 **미러 쪽
브랜치와 워킹트리 clean 여부뿐**이고, upstream 은 `--from`/`--to` refspec 으로만 읽는다. 그래서
upstream 로컬 클론이 다른 브랜치에 체크아웃돼 있거나 dirty 해도 dry-run·`--apply` 는 영향을 받지
않는다(2026-09-05 현재 `gstApp` 로컬이 그 상태다 — feature 브랜치 + dirty). 대신 `--from`/`--to`
를 `HEAD` 로 주면 그 체크아웃된 브랜치를 가리키므로, **기준 브랜치를 쓰려면 `master` 처럼 이름을
명시**한다.

### `pim-summit-backports` 가 부적합인 이유

"조사하지 않았다"가 아니라 **조사한 결과 부적합**이다. 큐레이션 축 자체는 실재한다 — 내용이 다른
공통 파일 3개(`.gitignore` · `README.md` · `make-for-imx8`)와 미러 전용 2개
(`docs/pim-package-binary.md` · `docs/team-sharing-build-guide.md`)가 있다. 문제는 다섯 축 중
**두 축의 실측 후보가 0개**라는 것이다.

- **`UPSTREAM_ONLY` 후보 0** — upstream 전용 파일은 `.clangd` 하나뿐인데, 이 파일은 2026-08-25
  clangd 커밋들이 추가한 **upstream 신기능**이고 미러가 아직 받지 못한 것이다(미러의 `.gitignore`
  와 `make-for-imx8` 은 분기점 `6605bac` 와 바이트 단위로 같다). "미러에 두지 않는다"는 정책적
  사유가 없으므로 `UPSTREAM_ONLY` 가 아니다. `.clangd` 만 막으면 그 파일을 읽는 배선만 들어가고
  정작 `.clangd` 는 없는 반쪽 상태가 된다.
- **`FORBID` 후보 0** — upstream 에 있고 미러에 0건인 문자열은 clangd 계열뿐이다(2026-09-05 실측,
  upstream/mirror 파일 수: `compile_commands.json` 3/0, `clangd` 3/0, `.clangd` 1/0). 그런데 그
  문자열을 담은 upstream `make-for-imx8` 이 정상 복사되는 순간 `ASSERT_B` 가 확정적으로 실패해
  `--apply` 가 영구히 불가능해진다. max9296 선례 문자열은 전부 upstream 0건이라 애초에 후보가
  아니다(`PR #` 0/0, `pull/` 0/0, `.github` 0/0, `docs/superpowers/` 0/0).

두 축을 추측으로 채우는 것 말고는 방법이 없고 **그 추측 자체가 오류**이므로 conf 를 만들지 않았다.
축이 비면 스크립트가 종료 코드 2 로 거부하므로 억지로 통과시킬 수도 없다. 이 쌍의 미러 기본
브랜치는 `main` 이 아니라 `develop` 이라는 점도 기록해 둔다(현재 `develop` == `main` == `badf083`).

`pairs.tsv` 에서 이 행을 **주석 상태로 두는 이유**는 처음과 같다: 행이 살아 있으면 없는 conf 를
참조하거나 빈 규칙으로 "미반입 0건 / 보존 0건"을 출력해 **조용히 전량 복사**하게 된다. 이슈 #34 가
지적한 사고와 정확히 같은 실패 방식이다. 없는 pair 를 `--pair` 로 주면 종료 코드 2 와 함께 사용
가능한 pair 목록이 표시된다.

### "표본 하나로 추상화하지 않는다" — 4쌍을 재보니

이슈 #34 는 표본 하나로 5쌍 공용 추상화를 만들지 않기로 못박고, 두 번째 쌍을 실제로 싱크할 때
공통점이 드러나면 그때 일반화하기로 했다. 4쌍을 실측한 결과는 **그 판단을 지지한다.** 근거는
세 가지이고 전부 2026-09-05 실측이다.

**첫째, 내용 축(`FORBID`)은 쌍 간에 옮겨 쓸 수 없다.** max9296 의 세 문자열을 나머지 세 쌍에
그대로 적용했을 때의 실측값이다(`git grep -lF`, upstream `master` / mirror `main` 파일 수).

| 문자열 | max9296 | gstApp | imx-vpu | sc16is7xx |
|---|---|---|---|---|
| `PR #` | up 2 / mi 0 ✅ | up 10 / **mi 2** ❌ | up 1 / **mi 1** ❌ | up 0 / mi 0 (죽은 항목) |
| `pull/` | up 1 / mi 0 ✅ | up 0 / mi 0 (죽은 항목) | up 0 / mi 0 (죽은 항목) | up 0 / mi 0 (죽은 항목) |
| `docs/superpowers/` | up 6 / mi 0 ✅ | up 3 / mi 0 ✅ | up 0 / mi 0 (죽은 항목) | up 0 / mi 0 (죽은 항목) |

공용 `FORBID` 목록을 만들어 그대로 복사했다면 **gstApp 과 imx-vpu 는 첫 `--apply` 부터
`ASSERT_B` 실패**였고(미러에 이미 있는 문자열이므로 고칠 방법도 없다), sc16is7xx 에서는 세 항목이
전부 아무것도 지키지 않는 죽은 문자열이었다. `FORBID` 는 죽은 패턴 경고 대상이 아니라서 그
무효화는 조용하다. 네 conf 의 `FORBID` 는 3 / 5 / 4 / 5 = 17개이고 **고유 문자열은 13종**이다.
두 쌍에 함께 나타나는 것은 4종뿐이며(`docs/superpowers/` 는 max9296·gstApp, `clangd` ·
`compile_commands.json` · `.github/` 는 imx-vpu·sc16is7xx), **네 쌍 모두에 들어가는 문자열은
하나도 없다.**

**둘째, 경로 축에서 공통인 것은 "규칙"이 아니라 "모양"뿐이다.** 네 conf 전부 `.gitignore` 를
`KEEP_MIRROR` 에 갖고, `.github/**` 를 `UPSTREAM_ONLY` 에 가지며, `MIRROR_ONLY` 는 정확히 1개다
(그 1개가 `docs/pim-package-binary.md` 인 쌍이 4쌍 중 3쌍이고, pim 의 미러 전용 파일에도 같은
경로가 있다). 하지만 규모는 `UPSTREAM_ONLY` 277개/19패턴 ↔ 14개/3패턴으로 20배 가까이 벌어지고
`KEEP_MIRROR` 도 6 ↔ 1 이다. 공용화할 수 있는 것은 새 conf 를 시작할 때 붙여 넣을 **두세 줄짜리
출발점**이지 규칙 엔진이 아니다.

**셋째, max9296 에서 규칙처럼 보였던 관행 하나는 표본의 우연이었다.** max9296 conf 는
`KEEP_MIRROR` 6개 **전부**에 `MUST_SURVIVE` 문자열을 1:1 로 대응시켰고, 이 문서도 그것을 새 쌍
추가 절차에 규칙으로 적어 두었다. 4쌍의 `KEEP_MIRROR` 15개를 실측하니 **12개만 그렇게 앵커할 수
있다.** 나머지 3개(imx-vpu `.gitignore`, sc16is7xx `.gitignore`·`make-for-imx8`)는 미러 판이
upstream 판의 **진부분집합**이라(줄 단위 비교에서 미러에만 있는 줄 0) 미러 전용 문자열이 원리적으로
존재하지 않는다. 두 conf 는 그 세 자리를 `FORBID` 로 대신 덮었고, 실측으로 그것이 동작한다 —
세 파일 모두 upstream 판에는 `clangd`·`compile_commands.json` 이 있고 미러 판에는 0건이라
덮이는 순간 `ASSERT_B` 가 잡는다. 즉 측정에서 살아남는 불변식은 "`KEEP_MIRROR` 마다
`MUST_SURVIVE`" 가 아니라 **"`KEEP_MIRROR` 마다 `MUST_SURVIVE` 또는 `FORBID` 중 하나로
앵커한다"** 는 더 약한 형태다. 위 [새 쌍 추가](#새-쌍-추가) 2번을 이 형태로 고쳤다.

**한편 스크립트는 한 줄도 고치지 않았다.** 새 축도, glob 문법 확장도, 우선순위 변경도 필요하지
않았다. 파일 이름이 서로 다른 대응 쌍(imx-vpu 의 upstream `make-for-imx8.sh` ↔ 미러 `build.sh`)
조차 `UPSTREAM_ONLY` 한 줄 + `MIRROR_ONLY` 한 줄로 정확히 표현되고 dry-run 으로 확인됐다 —
`RENAME_MAP` 같은 새 축은 필요 없었다. 반대로 스크립트 쪽에서 다시 볼 만한 것으로 **다섯 축이
전부 비어 있지 않아야 한다는 제약**이 드러났다. 그 제약이 `pim-summit-backports` 를 부적합으로
만든 유일한 원인이고, 축이 빈 것과 축을 조사하지 않은 것은 다른 상태다. 이것과 위 셋째 항목의
불변식 강제 여부는 **판단이 필요한 사안이라 이번 범위에서 구현하지 않았다.**

결론: 네 번째 쌍까지 재본 지금도 **일반화할 것은 규칙이 아니라 규약이다.** 쌍마다 conf 한 장을
추가하는 현재 구조를 유지한다.

## 테스트

```bash
./tests/mirror-sync-test.sh
```

쓰기가 있는 모든 검사는 `mktemp -d` 로 만든 **mock git 저장소**에서만 돈다. 실제 미러 쌍을
대상으로는 마지막 절의 **dry-run(순수 읽기)** 스모크 하나뿐이다.

어서션 6종은 전부 **최소 쌍**으로 두 번 돈다 — 위반 사실 하나를 심은 세계에서 그 어서션이
`[FAIL]` + 종료 코드 4 + 커밋 없음이고, 그 사실 하나만 되돌린 세계에서 `[PASS]` + 종료 코드 0 +
커밋 1개여야 한다. 두 세계의 차이가 그 사실 하나뿐이므로 한쪽만 보면 아무것도 검증하지 못한다.
나머지 어서션이 그 실행에서 `[PASS]` 인 것도 함께 확인한다.

`A`·`D` 의 위반 세계만 미러 base 커밋에 심는다. 분류와 어서션이 같은 패턴을 쓰고 `--apply` 는
clean 한 미러에서만 시작하므로 **싱크 자신이 A·D 위반을 만들 수 없기 때문**이다(그 대신 5-P 가
"upstream 이 `MIRROR_ONLY` 파일을 지워도 미러에서는 지우지 않는다"를 실물로 확인한다).
분류가 틀려 파일이 새어나가는 시나리오는 A 가 아니라 `ASSERT_F` 의 몫이다.

배포 conf(`config/curation/max9296.conf`) 스모크는 실제 두 저장소와 기준 커밋이 있는 호스트에서만
돌고, 없으면 `SKIP` 으로 집계에 남는다(조용히 빠지지 않는다). 나머지 검사는 전부 mock 전용 conf 를
주입하므로 이 스모크가 없으면 배포 conf 의 오타·패턴 누락은 회귀 테스트로 하나도 걸러지지 않는다.

**이 스모크는 `max9296` 하나만 대상으로 한다.** 2026-09-05 에 추가한 `gstApp` · `imx-vpu` ·
`sc16is7xx` conf 는 위 [실측 기준값](#실측-기준값)의 dry-run 으로 한 번 확인했을 뿐 **회귀
테스트가 없다.** 그 세 conf 의 패턴이 나중에 죽어도 `./tests/mirror-sync-test.sh` 는 통과한다.
